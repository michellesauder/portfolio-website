# Overview

A production‑grade **web demo** showcasing **Amazon IVS Realtime** (WebRTC) with **sub‑300ms end‑to‑end latency**, built to demonstrate modern multi‑participant live video directly in the browser. The app implements **stage creation**, **host/guest controls**, **viewer mode**, **device management**, **screen share**, and **moderation** with a clean, responsive UI. It was presented by Amazon at a conference in **Japan**, where it served as the canonical example of how to build interactive live experiences on IVS Realtime with React.

# My Role & Scope

* **Lead implementer (contract):** Shipped the React/Next.js frontend, auth & token flow, and the infra glue that connects browser clients to IVS Realtime Stages.
* **Demo hardening:** Turned sample code into a **conference‑ready showcase**: error states, device fallbacks, connection health, and UX polish.
* **Developer enablement:** Wrote concise docs and inline guidance so teams can extend the demo for their own use cases (townhalls, shoppable video, classrooms).

# Problem

Live video is easy; **interactive, multi‑host live** at **WebRTC‑level latency** is hard. Teams struggle with:

* Managing **stage roles** (host/guest/viewer) and participant lifecycles.
* Securely issuing **ephemeral participant tokens** server‑side.
* Handling **device permissions**, network variability, and reconnections with dignity.

# Solution

A modular React app that demonstrates the **end‑to‑end flow**:

1. **Auth** → (Cognito/JWT) identifies user & role.
2. **Token service** → AWS Lambda issues **short‑lived IVS Realtime tokens**.
3. **Join stage** → Client SDK publishes/subscribes media; role‑based UI gates controls.
4. **Moderation** → Host admits/kicks, toggles AV, sets max participants.
5. **Resilience** → Connection state machine with clear user feedback and retry.

# Architecture (High Level)

```
[Client (Next.js/React)]
  ├─ Auth (Cognito/JWT)
  ├─ Stage UI (Host/Guest/Viewer)
  ├─ Device & Media (getUserMedia, screenshare)
  └─ IVS Realtime SDK (publish/subscribe)
        │
        ▼
[API Gateway] → [Lambda token service] → [Amazon IVS Realtime Stages]
        │
        └─ (Optional) metrics/logs → CloudWatch

Static hosting: S3 + CloudFront
IaC: AWS CDK
```

# Selected Challenges & How I Solved Them

* **Device permission edge cases**: Added progressive prompts and fallbacks (default devices, hot‑swap handlers) so users never land in a "dead" state.
* **Network volatility**: Implemented a lightweight **connection state machine** with exponential backoff and user feedback; preserved UI state between reconnects.
* **Role‑based gating**: Centralized capability checks (e.g., only hosts can admit/kick) to keep UI logic simple and auditable.

# How to Run Locally (excerpt)

1. Clone repo & install deps
2. Provision IVS Realtime stage and token service (CDK or CloudFormation)
3. Set env vars for **TOKEN_API_URL** and auth provider
4. `npm run dev` → open the app with two browser windows to simulate host/guest

# Amazon IVS UGC Platform Web Demo

A comprehensive **User-Generated Content (UGC) live streaming platform** built with Amazon IVS, demonstrating how to create a full-featured streaming service with user authentication, live video playback, live chat, and stream monitoring.

## Project Overview

This educational demo showcases a complete UGC platform architecture using Amazon IVS in conjunction with other AWS services. The platform enables users to create accounts, go live, interact with viewers through chat, and provides comprehensive stream analytics and monitoring capabilities.

## Technical Implementation

### Core Platform Features
- **User Registration & Authentication**: Amazon Cognito integration with sign-up, login, and password reset flows
- **Live Streaming**: Amazon IVS integration for low-latency video streaming
- **Live Chat**: Real-time messaging system for viewer interaction
- **Stream Management**: Channel creation, stream monitoring, and analytics
- **Interactive Experiences**: Virtual experiences and engagement features

### Architecture Components
- **Frontend**: React-based web application with responsive design
- **Backend**: ECS Fargate service with Application Load Balancer
- **Database**: DynamoDB tables for channels and stream metrics
- **Authentication**: Cognito User Pool with Lambda triggers
- **CDN**: CloudFront distribution for global content delivery
- **Infrastructure**: AWS CDK v2 for Infrastructure as Code

### AWS Services Integration
- **Amazon IVS**: Interactive Video Service for live streaming
- **Amazon Cognito**: User authentication and management
- **DynamoDB**: Data storage for channels and metrics
- **ECS Fargate**: Containerized backend services
- **API Gateway**: RESTful API endpoints
- **EventBridge**: Event-driven architecture for IVS events
- **Lambda**: Serverless functions for user management and cleanup
- **Secrets Manager**: Secure credential management
- **CloudWatch**: Monitoring and logging
